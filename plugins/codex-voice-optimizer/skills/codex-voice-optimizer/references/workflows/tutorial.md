# Workflow: Tutorial

Tutorial is a named, opt-in onboarding process that teaches the user the
optimized voice system by using it, not by lecturing about it. It runs like a
good app dashboard tour: short segments, each ending with the user doing the
thing once, substantive but quick. Basics complete in a few minutes of real
interaction; advanced content is offered afterward and delivered only if the
user accepts.

## Invoke the tutorial

Anchors:

> Start the voice optimizer tutorial.

Also activate on any clear ask to learn or be taught how the voice system
works ("teach me how to use this," "how does this voice thing work,"
"onboard me"). Offer it proactively at most once, only when the user seems
new to the skill — never mid-workstream.

## Teaching rules

- Teach hands-on. Every concept ends with the user performing it once,
  preferably against their real work; fall back to a harmless sample task
  only when no real work exists yet.
- Keep each segment to a few sentences of speech plus one user action. No
  segment is a lecture.
- All base-layer rules apply while teaching: lettered choices, outcome-first
  speech, no interruptions, authority preserved. The tutorial itself models
  the behavior it teaches.
- Never demonstrate a capability the current session lacks; skip it and say
  so in one sentence.
- The user can bail at any point ("that's enough") — close immediately with
  the recap, no protest.

## Basics (the tour)

Run these segments in order:

1. **The model, in one breath.** You speak; this thread routes; named work
   threads do the work; material results come back as speech. This thread
   never does the work itself.
2. **Delegate something.** Have the user name an existing work thread or ask
   for one, then delegate a small real task by voice. Narrate what was
   dispatched in one sentence.
3. **Updates come to you.** Explain that threads report at material
   boundaries — progress, blockers, readiness — and that unchanged status is
   never narrated. When the first real update arrives, tag it: "that was a
   checkpoint; you'll hear these as they happen."
4. **Interrogate anything.** Have the user ask to elaborate, clarify, or
   simplify the last update — the replacement for reading model output.
5. **Visible artifacts.** Have the user ask for something in the chat pane —
   a clickable file path, a list — and deliver it via the inline route.
6. **Authority.** One sentence: nothing is pushed, merged, published, or
   deployed without their explicit authorization of that specific action.

Close the basics with a one-breath recap of the six moves, then offer the
advanced tour in one sentence. If declined or ignored, stop; do not offer
again.

## Advanced (only on acceptance)

Pick the segments relevant to the user's context, same hands-on rules:

1. **Freeway.** N parallel lanes, lanes as roles, the two-lane starter, lane
   handles ("send that to the research lane"), the offer they'll hear at
   session start. Anchor: "run this on the freeway."
2. **Decision Walkthrough.** Converging authority decisions one packet at a
   time before implementation — read on screen, hear the compressed version,
   answer with a letter. Anchor: "start the decision walkthrough for this
   slice."
3. **Peer traffic.** Work threads message each other directly when lanes
   depend on each other; the user can broker by voice: "tell research to send
   that to the change lane."
4. **Corrections and recovery.** Correcting scope mid-flight, challenging a
   claim, and what honest failure handling sounds like.
5. **The roster.** They can always ask what workflows and modes are
   available.

End with the anchor phrases spoken once, slowly, and offer to drop them
inline as a cheat sheet.
